# v0.96 commercial quality screening (CQS)

SQS (existing static security/qualification), CQS (commercial quality) and GPS (real-user performance) are independent. New pending ZIP versions require SQS pass and completed CQS >=60 before manual approval. Legacy approved demos remain playable in Test Lab; rejected versions are not reopened. CQS is provisional and does not establish runtime safety, market demand or commercial readiness.

Evidence: existing ZIP and thumbnail plus 3–5 developer screenshots (PNG/JPEG/WebP, each <=1 MB; combined screenshots and thumbnail <=6 MB), controls, concept and AI use disclosure. Evidence is private; upload owner paths are immutable under existing storage policies. Consent required before external AI processing. SQS package hash is reverified before CQS; no URL fetch or uploaded code execution. At most 3 attempts per version, owner-level daily cap. API secrets stay in Edge Function environment. CQS engine uses existing OPENAI_API_KEY.

Rubric: 0 absent/unusable, 1 rudimentary, 2 functional but material improvement required, 3 service-level evidence, 4 unusually polished. Weighted maxima graphics 20, UX 15, gameplay 20, content 15, technical 10, audio 5, originality 10, service readiness 5. Server totals weighted levels and rounds to integer. Worker caps technical at level 2 without measured runtime and originality at 3 without external comparison. Current genre rubrics Arcade/Action/Puzzle. D <60 needs revision, C 60–69 Test Lab, B 70–79 service, A 80–89 service, S 90+ service. The labels are triage categories, not certification; final human review is required. Candidates in the admin UI need service class, CQS >=80 and GPS >=80 with existing sample gate. Existing publishing applications remain unchanged. Actual gameplay and isolated malicious-file/runtime validation remain separate future work.

Acceptance: new version with thumbnail; pass SQS; submit screenshots and controls/concept/AI-use and consent in Creator Studio; invoke CQS; verify report and grade; verify below 60 blocked, C and B classes; human preview trusted fixture only; approve after actual QA; verify separate catalog filters. Automated browser tests use mocks and must not be represented as real API integration tests. No production test data created for SQL rollback QA.
